## Chapter 5: Task Decomposition and Memory Systems — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Short-term (working) memory vs Long-term memory — key distinguishing factor? | Short-term/working memory holds context only for the current session (intermediate state, scratchpad); long-term memory persists across sessions. Exam tip: 'cross-session' in the scenario = long-term memory is required. |
| 2 | Episodic memory — definition and example | Stores specific past interactions/events with context (who, what, when). Example: recalling an exact prior conversation. Exam tip: look for 'specific past conversation' language in scenarios. |
| 3 | Semantic memory — definition and example | Stores generalized, de-contextualized facts not tied to a specific event. Example: 'the user is allergic to peanuts' stored as a general fact rather than the conversation where it was mentioned. Exam tip: 'generalized fact' language = semantic memory. |
| 4 | When should you choose long-term memory over working memory in a scenario question? | Choose long-term memory when the scenario mentions persistence across sessions, days, or multiple conversations. Choose working memory when the scenario is confined to the current single session. |
| 5 | Purpose of summarization/compaction in agent memory systems | Condenses older conversation turns into a compact running summary to manage growing context and avoid exceeding context limits, while preserving key facts and the active goal. |
| 6 | Task decomposition pattern for long-horizon goals with step dependencies | Hierarchical decomposition with checkpoints: break the goal into sub-goals, execute, re-evaluate the plan using new information, and adjust remaining steps. Avoid static upfront-only planning when dependencies exist. |
| 7 | How does an agent avoid losing sight of the original goal across many steps? | Re-inject/restate the original goal into context at each planning or decomposition checkpoint (goal-anchoring or scratchpad pattern), rather than relying on it remaining implicitly in the conversation history. |
| 8 | Scenario clue: 'agent must recall the exact wording/date of a prior conversation' → which memory type? | Episodic memory — it stores specific past interactions with contextual details (timing, exact content), unlike semantic memory's generalized facts. |
| 9 | Scenario clue: 'agent must apply a generalized fact about the user or domain regardless of when it was learned' → which memory type? | Semantic memory — it stores de-contextualized, generalized knowledge rather than a record of a specific interaction. |
| 10 | Risk of blind context truncation vs summarization/compaction | Blind truncation (dropping oldest messages outright) risks losing critical facts or the active goal, causing task drift. Summarization/compaction preserves essential facts in condensed form, maintaining continuity. |
| 11 | Working memory — typical failure mode if goal isn't reinforced | As working memory accumulates intermediate tool outputs and reasoning steps over a long-horizon task, the original objective can be crowded out, causing the agent's later outputs to drift from the user's actual request. |
| 12 | Cross-session personalization requirement → required memory architecture | Persist user-specific facts to long-term memory AND retrieve relevant entries at the start of each new session. Working memory alone cannot satisfy cross-session recall regardless of context window size. |
