## Chapter 1: Anatomy of an LLM Agent — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the four stages of the agent cognition loop? | Perception → Reasoning → Action → Reflection. Exam tip: reflection is what distinguishes a self-correcting agent from a simple reactive tool-caller. |
| 2 | ReAct pattern — what does it interleave? | Thought (reasoning) and Action (tool call), observing each result before the next thought. Exam tip: choose ReAct when the next step depends on live tool output. |
| 3 | Plan-and-execute vs ReAct — key difference? | Plan-and-execute generates the full plan upfront then executes it; ReAct decides one step at a time based on live observations. Exam tip: use plan-and-execute for predictable workflows, ReAct for dynamic/uncertain ones. |
| 4 | Chain-of-thought (CoT) vs Tree-of-thought (ToT)? | CoT = single linear reasoning path. ToT = branches into multiple candidate paths, evaluates/backtracks, then selects the best. Exam tip: ToT costs more tokens/latency — reserve it for problems that benefit from exploring alternatives. |
| 5 | When does a single well-tooled agent beat a multi-agent team? | When task scope is narrow, tools are few, and there's low need for parallel specialized reasoning — multi-agent adds coordination overhead without benefit. Exam tip: default to single-agent unless the scenario truly needs role specialization. |
| 6 | What is a deterministic control boundary in agent design? | A hard-coded rule/gate (e.g., human approval, allow-list) that constrains autonomous behavior for specific high-risk actions. Exam tip: 'approval required before X' language = deterministic boundary on autonomy. |
| 7 | What is a self-reflection / self-critique loop? | The agent evaluates its own output against goal/criteria and revises before finalizing. Exam tip: must be bounded (max iterations) — unbounded reflection risks infinite loops with no guaranteed improvement. |
| 8 | System-prompt best practice: persona vs safety constraints? | State hard safety/tool-use constraints with explicit priority over persona/tone instructions, not buried after a long persona backstory. Exam tip: scenarios testing 'can persona override safety rules?' are fixed by prioritized, explicit constraints. |
| 9 | Reasoning stage of the agent loop — what happens? | The agent decides the next action based on current state/goal using the LLM to plan a step. Exam tip: don't confuse with reflection, which evaluates the outcome of a past action. |
| 10 | Perception stage of the agent loop — what happens? | The agent ingests raw input/observations from the environment or tool output. Exam tip: perception recurs every loop iteration, including re-observing tool results mid-task. |
| 11 | Why bound reflection-loop iterations? | Unbounded self-critique can loop indefinitely or add latency/cost without guaranteed quality gain. Exam tip: production designs cap reflection at a small fixed number of iterations or use a convergence check. |
| 12 | Multi-agent team — when is it justified over a single agent? | When the task needs distinct specialized roles working in parallel, conflicting objectives requiring negotiation, or a tool/context set too large for one agent's context window. Exam tip: 'narrow scope, one knowledge base, two tools' scenarios → single agent, not multi-agent. |
